## Theory

`DENSE_RANK()` работает как RANK, но не оставляет «дыр» в нумерации после связки: 1, 2, 2, 3 (а не 1, 2, 2, 4).

```sql
DENSE_RANK() OVER (ORDER BY столбец DESC)
```

## Example

Те же два товара по цене 1000 на 2-м месте — DENSE_RANK присвоит им ранг 2, а следующий товар получит ранг 3.

## Common mistakes

- Выбирать RANK, когда по смыслу задачи (например, топ-N уникальных ценовых уровней) нужен именно DENSE_RANK.
